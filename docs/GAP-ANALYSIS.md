**The catalogue has 89 rows, not 90.** Two instruments agree: `Import-PowerShellDataFile`
returns an `Entry` array of 89, and a search of the reference `PORT-PLAN.md` and `docs\SPEC.md`
for `ADA-<AREA>-<nnn>` finds 89 unique ids, the same 89. Neither instrument can see a row that
was planned and never given an id.

What the states mean here:

- **Covered** - the target produces an equivalent verdict, or equivalent inventory, from
  equivalent data.
- **Partly** - related data is collected, but the rule is different or weaker, the thresholds
  are missing, the transport differs, or the catalogue has a verdict where the target has
  inventory only. The Evidence column says which.
- **Missing** - nothing equivalent. Each Missing row cites two instruments: a named search of the
  script that found nothing relevant, and the `-Sections` ValidateSet or README coverage table.

For an **Inventory** row, Covered means the data is collected. The reference tool gives those
rows no verdict either.

## How this was produced, and what that cannot see

Eight read-only agents each mapped a group of catalogue rows to the target script, and a ninth
audited the target's README and help text against its code. Their output is reproduced in the
tables below with paths shortened and nothing else changed.

Limits a reader should hold against every row:

- **The rows were not individually re-verified.** The author spot-checked four claims directly
  (listed under "Spot-checks") and the row counts. Every other evidence cell is one agent's
  reading of the code. Treat a line number as a pointer to check, not as proof.
- **Nothing was run against a directory.** Every statement about behaviour comes from reading
  code, not from executing it. Statements about what a cmdlet returns in a real forest are
  inferences.
- **Vendor facts in the "Data source" column come from the reference repository's recorded
  facts** (its `## Learn facts` rows, read 2026-09-24 and 2026-09-25). They were **not** re-read on
  Microsoft Learn for this analysis. Each must be re-read, with URL and date, in the session that
  builds the check.
- **32 rows contain the word UNKNOWN** where an agent could not determine something from the two
  repositories. Those are open questions, not findings.
- **The proposed `-Sections` names are proposals.** Eight are new: `DcSystem`, `DcDisk`, `Laps`,
  `DcCertificates` and `RidPool` for the priority checks, and `GroupInventory`, `DcEvents` and
  `DnsRecordExport` for inventory. Existing values are reused wherever the check belongs in an existing section.
